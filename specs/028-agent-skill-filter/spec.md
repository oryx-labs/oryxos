# Feature Specification: 新建 Agent 时的已安装 Skill 查询筛选

**Feature Branch**: `028-agent-skill-filter`

**Created**: 2026-09-01

**Status**: Draft

**Input**: User description: "新建 Agent 时，支持已经安装 SKILL 的查询筛选——这样在 SKILL 量特别大的时候，找到对应 SKILL 会更加容易"

## Clarifications

### Session 2026-09-01

- Q: 筛选范围只做新建页，还是新建 + 详情编辑页都做？ → A: 新建页 + 详情编辑页都做（编辑页为 P2，可独立降级，不影响 P1 独立交付）。
- Q: 当筛选把已勾选的 Skill 隐藏时，要不要给提示？ → A: 显示「N 项已选被当前筛选隐藏」提示，可点击临时把它们纳入视野。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在新建 Agent 时按关键词筛出要绑定的 Skill (Priority: P1)

管理员在新建 Agent 的「Skill 绑定」一栏，看到一个搜索框；输入关键词后，下方的已安装 Skill
勾选列表实时收窄到名称或描述命中关键词的那些。当 Skill 库很大（几十甚至上百个）时，不必在一长串
平铺的复选框里肉眼定位，打几个字就能锁定要绑的那一两个。

**Why this priority**: 这是本特性的核心用户价值——解决「SKILL 量特别大时找不到要绑的那个」这个
具体痛点。没有这一条，特性本身不成立。

**Independent Test**: 安装 30 个 Skill（其中 5 个名称或描述含 "pr"），打开新建 Agent 页，在搜索框
输入 "pr"；结果列表只剩这 5 个，其余 25 个被隐藏，不滚动即可一眼看全。

**Acceptance Scenarios**:

1. **Given** 已安装多个 Skill，**When** 管理员打开新建 Agent 视图，**Then** Skill 绑定区上方出现
   一个搜索框，下方仍列出全部已安装 Skill 供勾选。
2. **Given** 搜索框为空，**When** 列表渲染，**Then** 显示全部已安装 Skill，行为与未加搜索框前一致。
3. **Given** 管理员在搜索框输入关键词，**When** 每次键入，**Then** 列表实时收窄为名称或描述
   （不区分大小写）命中的 Skill；不命中的不显示。
4. **Given** 搜索结果为空，**When** 列表渲染，**Then** 显示一条明确的「无匹配 Skill」提示，而非空白。
5. **Given** 搜索框有内容，**When** 管理员清空搜索框，**Then** 列表恢复显示全部已安装 Skill。

---

### User Story 2 - 筛选不丢已勾选状态 (Priority: P1)

管理员可以先勾选若干 Skill，再输入关键词筛选别的 Skill；被筛选隐藏的、已勾选的 Skill 仍保持选中，
不会被筛选动作悄悄取消。最终提交创建时，所有勾选过的 Skill 都生效，无论它们当前是否在筛选视野内。

**Why this priority**: 与筛选本身同级关键——如果筛选会清掉已选，管理员就不敢在选完之后再筛，
特性反而引入误操作风险。安全地「边选边筛」是 P1。

**Independent Test**: 勾选 3 个 Skill，在搜索框输入一个不命中这 3 个的关键词（列表只剩别的 Skill），
再清空搜索；原先勾选的 3 个依旧处于勾选态，可正常提交创建。

**Acceptance Scenarios**:

1. **Given** 管理员已勾选 Skill A 与 B，**When** 输入关键词只命中 Skill C（A、B 不显示），
   **Then** 列表只显示 C；A、B 虽不可见但其选中状态被保留，不被取消。
2. **Given** A、B 已选且当前被筛选隐藏，**When** 管理员清空搜索框，**Then** A、B 重新可见且仍为勾选态。
3. **Given** A、B 已选且当前被筛选隐藏，**When** 列表渲染，**Then** 出现一条「当前筛选隐藏了 2 项已选」提示；
   管理员可点击该提示临时把 A、B 纳入视野（选中态不变），无需清空关键词。
4. **Given** 作者模型此前建议并已合并进绑定的 Skill，**When** 管理员随后筛选，**Then** 建议项同样
   遵循「可见即受筛、已选不丢」规则，不会被静默取消。

---

### User Story 3 - 批量勾选当前筛选结果 (Priority: P2)

当筛选出多个相关 Skill 时，管理员可以一键全选「当前筛选视野内」的 Skill，或一键清空当前视野内的
勾选，而不必逐个点。这对「一次要绑一整类 Skill」的场景省力。

**Why this priority**: 提升效率但非阻塞——没有它，逐个勾选仍可达成目标，只是慢。P2。

**Independent Test**: 搜索 "git"，结果 4 个；点「全选当前」，4 个全部勾选；点「清空当前」，4 个全部
取消；视野外的已选项不受影响。

**Acceptance Scenarios**:

1. **Given** 搜索结果列出 N 个 Skill，**When** 管理员点「全选当前」，**Then** 这 N 个全部变为勾选态；
   视野外已选的 Skill 不受影响。
2. **Given** 当前视野内若干项已勾选，**When** 管理员点「清空当前」，**Then** 仅当前视野内的勾选被取消；
   视野外已选的 Skill 仍保持选中。
3. **Given** 搜索结果为空，**When** 视野内无项可操作，**Then** 「全选当前 / 清空当前」不可用或无效果。

---

### User Story 4 - Agent 详情页编辑绑定时同样可筛选 (Priority: P2)

管理员在 Agent 详情页的「基本信息 > skills」编辑绑定区，使用的是与新建页同一个 Skill 选择器，因此
同样具备搜索筛选能力。已有绑定的 Agent 在增减 Skill 时也能享受一样的筛选便利。

**Why this priority**: 同一痛点在编辑场景重现；复用选择器让两处一致是自然延伸，但用户原话聚焦
「新建 Agent 时」，故列为 P2。

**Independent Test**: 打开任一已存在 Agent 的详情页，基本信息里 skills 区出现与新建页一致的搜索框；
输入关键词，列表同样收窄，已有绑定项的勾选态在筛选中保留。

**Acceptance Scenarios**:

1. **Given** 管理员打开某 Agent 详情页进入基本信息编辑，**When** 查看 skills 区，**Then** 出现与新建页
   一致的搜索框与同样的筛选行为。
2. **Given** 该 Agent 已绑定 Skill X，**When** 输入关键词不命中 X，**Then** X 被隐藏但保留勾选态；
   清空搜索后 X 仍为已选，保存绑定后 X 仍生效。

---

### Edge Cases

- 搜索关键词含前导/尾随空格或大小写混用：按去除首尾空格、不区分大小写匹配，避免「看起来该命中却没命中」。
- 仅搜索框首尾空格的纯空串：视为空搜索，显示全部，而不是显示「无匹配」。
- 已安装 Skill 数为 0：搜索框可显示但无可筛内容，沿用现有「暂无已安装 Skill」空态提示，不另报错。
- Skill 的描述字段为空或缺失：仅按名称参与匹配，不报错、不影响其他项。
- 极多 Skill（如 200+）下输入极速连打：筛选应在合理时间内完成，不卡死页面、不丢失键入。
- 「N 项已选被当前筛选隐藏」提示中 N 的计数，应随筛选与勾选变化实时更新；点开「纳入视野」后，
  若管理员又改了关键词导致这些项再次被隐藏，提示计数与行为随之刷新，不留陈旧数字。
- 筛选期间触发了「用大模型生成」带来的作者建议 Skill 合并：建议项进入绑定后同样受「已选不丢」保护，
  不因随后筛选被静默取消。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在新建 Agent 视图的「Skill 绑定」区提供一个文本搜索框。
- **FR-002**: 系统 MUST 在管理员每次输入时，实时将下方 Skill 勾选列表收窄为名称或描述命中关键词
  （去首尾空格、不区分大小写）的项。
- **FR-003**: 系统 MUST 在搜索结果为空时显示明确的「无匹配 Skill」提示，而非空白区域。
- **FR-004**: 系统 MUST 保证筛选只影响显示，不影响已勾选状态——被筛选隐藏的已选项保持选中。
- **FR-004a**: 系统 MUST 在当前筛选隐藏了已勾选 Skill 时，显示一条「N 项已选被当前筛选隐藏」提示；
  管理员可点击该提示临时把被隐藏的已选项纳入视野，选中态不变，且无需清空关键词。
- **FR-005**: 系统 MUST 在清空搜索框后恢复显示全部已安装 Skill，并保留此前所有勾选状态。
- **FR-006**: 系统 SHOULD 提供对「当前筛选视野内」项的一键全选与一键清空勾选能力（P2）。
- **FR-007**: 系统 MUST 在 Agent 详情页编辑 Skill 绑定时，复用同一套搜索筛选能力与同一选择器行为。
- **FR-008**: 系统 MUST 让作者模型建议并合并进绑定的 Skill 同样遵循「已选不丢」规则，筛选不取消它们。
- **FR-009**: 系统 MUST 在已安装 Skill 数为 0 时仍正常渲染搜索框，并沿用现有空态提示而非报错。

### Key Entities *(include if feature involves data)*

- **已安装 Skill 列表项**: 既有实体，每项含 `name` 与 `description`；本特性只读取这两字段做匹配，
  不引入新持久化数据。
- **Agent 的 Skill 绑定集合**: 既有概念（保存为 `agents/<name>/skills/<skill>` 相对软连接）；
  本特性不改变其存储形态，仅改变绑定 UI 的查找体验。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在已安装 50 个 Skill 的环境下，管理员能在 5 秒内通过输入关键词把目标 Skill 收窄到视野内并完成勾选，而不需要滚动浏览全部列表。
- **SC-002**: 任意筛选操作都不会改变已勾选的 Skill 集合——筛选前后，提交创建/保存绑定所生效的 Skill 集合完全一致。
- **SC-003**: 在已安装 200 个 Skill 的环境下，搜索框连打输入时筛选响应足够流畅，管理员感知不到明显卡顿（无具体毫秒承诺，以「不阻塞打字」为准）。
- **SC-004**: 新建 Agent 与 Agent 详情编辑绑定两处使用同一筛选交互，管理员无需学习两套不同的查找方式。

## Assumptions

- 筛选范围为「已安装」Skill（即 `.oryxos/skills/<name>/` 存在的本地公共 Skill 库），不涉及从远程
  Skill 市场或外部列表联网检索——外部建议列表的来源不变。
- 筛选为纯客户端即时过滤：Skill 列表在进入新建/编辑视图时已加载完毕，本特性不新增后端接口、不新增网络请求。
- 用户原话聚焦「新建 Agent 时」，但因详情页编辑绑定复用同一选择器、同一痛点，本 spec 将两处一并覆盖；
  若只想先做新建页，可把 User Story 4 降级或移除，不影响 P1 故事独立交付。
- 筛选匹配字段取 Skill 的 `name` 与 `description`（与列表项现有展示字段一致），不引入对 SKILL.md
  正文的全文检索（正文按渐进式披露原则本就不在绑定阶段预载）。
- 既有「作者模型建议 Skill」的合并逻辑与保存为相对软连接的存储方式不变，本特性只在前端选择器层加查找能力。
