# Research: 034 淘宝/天猫店铺客服

**Date**: 2026-09-11  
**Status**: IN PROGRESS — **尚不可 BUILD**（须再钉死一条可自研路径与入驻门槛）  
**对照**: [030](../030-cn-c-im-roadmap/plan.md)

## 目标

官方直连：**买家 ↔ 店铺客服会话**由 Agent 收发文本。天猫与淘宝同 TOP → 单模块 `taobao`。

## 已排除的「假完成」路径

| 能力 | 为何不算店铺客服 IM |
|------|---------------------|
| TMC 交易/退款/物流主题 | 业务事件，不是聊天会话 |
| `taobao.jindoucloud.message.send` | 千牛**系统通知/服务号类目**；文档曾写内部调试；≠ 回买家旺旺 |
| 旺旺「亮灯」JSAPI（`openChat`） | 客户端唤起聊天窗，不是服务端收发 |
| 通用云旺 OpenIM（`openim.*.push`） | 独立 IM 账号体系，**不等于**手淘买家找店客服默认会话 |
| Cookie / 协议模拟千牛 | ❌ Won’t（违规） |

## 候选真路径（待收口）

### 候选 A：智能客服（机器人）+ 奇门

公开材料（飞猪/淘宝开放文档「智能客服」解决方案）：

- 消费者消息经 **奇门** 切到 ISV：`qimen.taobao.message.chatrobot.sync`（及关联 async）  
- 运行时网关形态如 `mappcloud-gw.taobao.com/invokeChatRobot/conversation`  
- 面向 **入驻智能客服/机器人解决方案的 ISV**，非任意 AppKey 即开即用  
- 含商家切流、云应用 `cloudAppId`、灰度等运营约束  

→ 若 OryxOS 以「商家自研 / ISV 入驻」身份接，这是目前最像「买家消息进 Agent」的官方面。  
→ **BUILD 前置**：确认入驻类目、权限包、沙箱、回复如何写回会话（同步响应 vs 另 API）。

### 候选 B：服务市场客服类插件协议

千牛应用平台「客服工具」类目历史悠久；大量第三方靠**服务市场 + 商家订购**拿消息。  
需核对：是否仍开放给自建 OS、协议是否等于候选 A。  
若只能「上架插件给商家订」——可接，但产品形态是 ISV，不是私有部署随手配 YAML。

## 隐私合规

买家标识走 `open_uid` / SecurityUID + bizDomain；禁用 nick 作为唯一键（平台脱敏改造）。

## 沙箱域名（若走 TOP/奇门）

- `gw.api.taobao.com` / `eco.taobao.com`  
- 奇门 / `mappcloud-gw.taobao.com`（以入驻文档为准）
