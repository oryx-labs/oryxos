# 飞书流式回复集成测试计划

## 测试目标

验证飞书渠道的流式回复功能（019 特性集成到 017），确保用户体验达到 OpenClaw 水平。

## 测试环境准备

### 1. 配置飞书应用

```yaml
# .oryxos/channels/feishu-test.yaml
name: feishu-test
type: feishu
enabled: true
bound_agent: default
app_id: ${FEISHU_APP_ID}
app_secret: ${FEISHU_APP_SECRET}
verification_token: ${FEISHU_VERIFICATION_TOKEN}
encrypt_key: ${FEISHU_ENCRYPT_KEY}
```

### 2. 启动 OryxOS

```bash
cd /path/to/oryxos
export FEISHU_APP_ID="cli_xxxx"
export FEISHU_APP_SECRET="xxxx"
export FEISHU_VERIFICATION_TOKEN="xxxx"
export FEISHU_ENCRYPT_KEY="xxxx"

# 启动守护进程
./bin/start.sh
```

### 3. 确认渠道就绪

```bash
# 查看日志
tail -f .oryxos/logs/oryxos.log | grep -i feishu
```

预期输出：
```
飞书渠道 feishu-test 启动成功
Stream 连接已建立
```

## 测试用例

### TC-01: 基础流式回复

**前置条件**：
- Agent 绑定了 `read_file` tool
- 工作区有测试文件 `.oryxos/test.txt`

**测试步骤**：
1. 在飞书私聊中 @ 机器人
2. 发送消息：「帮我读取 .oryxos/test.txt 文件」

**预期结果**：
1. **立即反馈**（< 500ms）：
   - 消息上出现 ⌨️ 表情（键盘图标）
   - 收到蓝色头部卡片「🤔 正在思考...」
   
2. **工具调用阶段**（约 1-3 秒）：
   - 卡片更新显示：
     ```
     思考过程：
     用户要求读取文件...
     
     工具调用：
     🔧 正在执行：read_file
     ```

3. **工具完成后**（约 2-5 秒）：
   - 卡片更新显示：
     ```
     思考过程：
     文件读取完成，准备回复...
     
     工具调用：
     ✅ read_file 完成
     ```

4. **最终回复**（约 3-8 秒）：
   - ⌨️ 表情消失
   - 卡片变为绿色头部「✅ 回答」
   - 显示完整的文件内容

**测试步骤**：
1. 发送消息：「帮我分析整个项目的代码结构」（触发多次工具调用）

**预期结果**：
1. 立即反馈：⌨️ 表情 + 初始卡片
2. **卡片持续更新**：

   - 工具调用列表动态刷新

   - **不会**额外发送「正在处理中」文本消息（流式路径已有卡片）

**预期结果**：
1. **降级为非流式**：
   - 不发送卡片
   - 不添加表情

## 性能指标

| 指标 | 目标值 | 测量方法 |
|------|--------|----------|
| 首次反馈延迟 | < 500ms | 消息发送到表情出现 |
| 卡片更新频率 | 每 200 字符或 1 秒 | 观察卡片刷新间隔 |
| 工具调用可见性 | 100% | 每次工具调用都有卡片更新 |
| 错误可读性 | 用户能理解 | 不含堆栈、技术术语 |

## 已知限制

1. **飞书 API 频控**：
   - 每个卡片最多每秒更新一次
   - 累积策略：每 200 字符或 1 秒更新一次

2. **思考过程展示**：
   - 只显示最近 5 行（避免卡片过长）
   - Token 按字符数累积（非语义分块）

3. **降级条件**：
   - 飞书 API 不可用 → 降级为纯文本
   - 表情添加失败 → 仍发送卡片
   - 卡片发送失败 → 降级为纯文本

## 故障排查

### 问题：表情没有出现

**可能原因**：
1. 飞书 API 权限不足（需要 `im:message:reaction:create` 权限）
2. 消息 ID 无效

**排查步骤**：
```bash
# 查看日志
grep "添加表情" .oryxos/logs/oryxos.log
```

### 问题：卡片没有更新

**可能原因**：
1. 卡片消息 ID 丢失
2. 飞书 API 频控

**排查步骤**：
```bash
# 查看卡片更新日志
grep "更新卡片" .oryxos/logs/oryxos.log
```

### 问题：降级为非流式

**可能原因**：
1. `FeishuMessageSender`、`FeishuReactionManager` 或 `FeishuCardBuilder` 未注入
2. 飞书 API 初始化失败

**排查步骤**：
```bash
# 查看渠道初始化日志
grep "渠道.*未就绪" .oryxos/logs/oryxos.log
```
