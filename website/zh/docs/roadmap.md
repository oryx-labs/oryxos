# 路线图

OryxOS 的开发理念是：**运行语义稳定、扩展能力开放、通过真实使用逐步验证**。先把可用的单节点 Agent Runtime 做扎实，再分阶段建设持久 Task、治理和分布式能力，每一步都通过真实使用验证。

路线图区分三种状态：

- **可用**——当前仓库已经实现并可使用。
- **演进中**——正在扩展，或正在统一到多个应用与部署形态。
- **探索中**——更长期的方向，仍需要设计、验证或社区共识。

## 可用 — 单机运行时内核

当前内核提供基础 Agent Runtime 及其扩展契约：

- 一个目录 = 一个 Agent：一个 `AGENT.md` 目录，无需写代码——放进去就上线
- 多 Agent 并存：同一实例上运行多个独立 Agent
- 动态 Agent 生命周期：通过 REST 创建 / 更新 / 删除 / 调用，一句话生成草稿，上传即上线 —— *已完成*
- REST API：对外暴露所有能力，响应统一信封
- `/admin/` Web 管理台：Agent 管理、定时任务、会话、工具及运行时视图 —— *已完成*
- 动态 Provider 注册表：以 SQLite 为后端的 Provider CRUD，运行时换密钥 —— *已完成*
- 通知渠道：以 SQLite 为后端的 CRUD（飞书 / 企业微信 / 钉钉 / webhook） —— *已完成*
- 定时任务：按 Agent 的定时任务，含管理和执行历史 —— *已完成*
- 通过 REST 的工作区文件浏览 —— *已完成*
- MCP 集成：零代码接入任意社区 MCP server
- 全链路审计：`tool_invocations` 和 `llm_calls` 第一天起就写入

**边界**：这是可用的单节点 Agent Runtime，并不等于完整的企业 Control Plane。持久 Task 生命周期、完整治理流程和跨应用优化属于后续路线图工作。

## 演进中 — Task Runtime 与 Control Plane

让企业 AI 工作在多个应用之间持久、受治理、可运营：

- 持久 Task 生命周期：排队、运行、等待审批、完成、失败、取消
- Checkpoint、重试、幂等、取消、恢复和 Artifact 语义
- 身份上下文、授权、Tool Policy、审批关口和可审计决策
- Trace、Metrics、Evaluation、成本归集、预算和回归反馈
- 面向应用与企业系统的稳定 Runtime API 和扩展契约

## 演进中 — 分布式基础

让运行时可以水平扩展：

- 实例无状态化：OryxOS 进程内不保留本地状态
- 状态外置：Session、记忆、审计数据存储在实例之外
- 多副本部署：多个 OryxOS 实例运行在负载均衡后面
- 高可用：消除单点故障

## 探索中 — 跨应用与 Agent 协作

在稳定的 Task 与治理语义之上支持更广泛的平台优化和多 Agent 协作：

- 跨应用的模型与能力优化
- 共享评测集、成本模型、策略反馈和运行经验
- 受治理的规划者、专家、评审者与 A2A 协作
- 跨节点 Agent 发现、委托和可靠消息投递
- 跨 Runtime、身份系统和执行环境的可移植扩展
